# Contract-First Runtime

The contract-first runtime is the deterministic semantic execution layer for
the OpenCode agent ecosystem. It enforces one mandatory architecture invariant:

```
LLMs ARE WORKERS.
LLMs ARE NOT THE CONTROLLER.
```

The ecosystem is `contract-first, not agent-first`. Contracts, gates, retry
authorization and terminal decisions live in deterministic runtime components.
There is no LLM majority decision, no parallel second orchestration layer, and
no new agent zoo. Workers (LLMs and agents) only produce validated contract
values; the runtime decides.

## Contracts

Ten versioned contracts live under `runtime/contracts/`:

| Contract ID | Module | Purpose |
|---|---|---|
| `ecosystem.task.v1` | `runtime/contracts/task.mjs` | Single source of a run; creates `run_id` |
| `ecosystem.baseline.v1` | `runtime/contracts/baseline.mjs` | Capability preflight result |
| `ecosystem.research.v1` | `runtime/contracts/research.mjs` | Research output |
| `ecosystem.plan.v1` | `runtime/contracts/plan.mjs` | Approved plan structure |
| `ecosystem.build-input.v1` | `runtime/contracts/build.mjs` | Build execution input |
| `ecosystem.build-result.v1` | `runtime/contracts/build.mjs` | Build execution result |
| `ecosystem.verification.v1` | `runtime/contracts/verification.mjs` | Deterministic verification outcome |
| `ecosystem.review.v1` | `runtime/contracts/review.mjs` | Independent review findings |
| `ecosystem.decision.v1` | `runtime/contracts/decision.mjs` | Terminal decision (controller only) |
| `ecosystem.run-event.v1` | `runtime/contracts/run-event.mjs` | Boundary observability event |

Each contract module exports `CONTRACT_ID`, `validate(obj)` returning
`{ ok, issues }`, and `create(...)`. The validators are pure `.mjs` modules
with no external schema dependency. `run_id` is created exclusively by the
task contract and only passed through by every other contract — it is never
regenerated by a later phase. `runtime/contracts/index.mjs` exposes the frozen
`CONTRACT_IDS` map and a `validateContract({ contract, value })` dispatcher
that routes to the matching validator and additionally enforces that the value
declares the expected `contract` field.

## Runtime Phases

`runtime/pipeline/pipeline.mjs` composes the ordered boundary sequence:

```
TASK → BASELINE → RESEARCH → PLAN → PLAN_GATE → BUILD → VERIFY → REVIEWS → CONTROLLER
```

- **TASK** — the task contract is created (or reused when a valid
  `ecosystem.task.v1` value is supplied); `run_id` originates here.
- **BASELINE** — capability preflight runs against the task and the native
  plan; the result is recorded as `ecosystem.baseline.v1`.
- **RESEARCH** — research is executed and wrapped in `ecosystem.research.v1`.
- **PLAN** — the native plan is mapped into `ecosystem.plan.v1` via the
  OpenCode adapter seam.
- **PLAN_GATE** — the deterministic, LLM-free plan gate evaluates the plan
  contract.
- **BUILD** — the build input contract is created and the native build
  executes; the outcome is wrapped in `ecosystem.build-result.v1`. A failed
  build may trigger a bounded retry inside this loop.
- **VERIFY** — real tool checks run; failures are normalized into stable
  `failure_signature`s and recorded as `ecosystem.verification.v1`.
- **REVIEWS** — independent analyzers (correctness, quality, security) run
  against the build result and produce `ecosystem.review.v1` values.
- **CONTROLLER** — the deterministic controller produces the terminal
  decision (`ecosystem.decision.v1`) with `first_bad_boundary` and
  `phase_history`.

The pipeline is deterministic and LLM-free: workers only provide validated
contracts, the controller decides. One `run_id` is preserved everywhere.

## Capability Preflight

`runtime/baseline/capability-detector.mjs` derives the capabilities a concrete
run actually needs from the task text and the plan — the preflight never probes
every installed capability. `runtime/baseline/capability-preflight.mjs` then
runs the checks. A missing required capability makes the baseline
`approved: false`, which blocks the run; a missing optional capability degrades
the run but does not stop it (the degradation is recorded). Credentials are
represented only as `AVAILABLE | MISSING | DENIED`; secret values are never
read, logged, or written into any contract. The MCP preflight reuses
`scripts/lib/mcp-preflight.mjs` (`runMcpPreflight`): required-tool failures are
fail-closed, optional-tool failures are recorded as degradations.

## Plan Gate

`runtime/controller/plan-gate.mjs` is a deterministic, LLM-free gate over
`ecosystem.plan.v1`. Minimum checks:

- plan exists,
- `acceptance_criteria` is non-empty,
- `build_scope` exists,
- `required_tests` is an array,
- `targets` is structurally valid (non-empty array of non-empty strings or
  objects with a non-empty `path`).

Reason codes: `PLAN_MISSING`, `ACCEPTANCE_CRITERIA_MISSING`,
`BUILD_SCOPE_MISSING`, `REQUIRED_TESTS_INVALID`, `TARGETS_INVALID`. The plan
worker cannot override this gate; the gate result is a deterministic value that
the controller consumes.

## Retry Policy

`runtime/controller/retry-policy.mjs` authorizes retries deterministically.
Retry is allowed only when ALL of the following hold:

- a `failure_signature` exists,
- a `strategy_delta` exists and is a real strategy change,
- `attempt < max_attempts` (default `2`),
- the identical failure is not a repeat: an identical `failure_signature`
  combined with the same/equivalent `strategy_delta` denies the retry.

Reason codes: `RETRY_ALLOWED_WITH_STRATEGY_DELTA`,
`RETRY_DENIED_NO_FAILURE_SIGNATURE`, `RETRY_DENIED_NO_STRATEGY_DELTA`,
`RETRY_DENIED_ATTEMPT_LIMIT`, `RETRY_DENIED_REPEATED_IDENTICAL_FAILURE`.
Invalid strategy deltas ("try again", "retry", "attempt another fix", and
similar non-strategic phrasings) are rejected; a delta must describe a concrete
strategy change (validated as ≥ 12 characters and not in the invalid set).
Retry denials are terminal for the run.

## Terminal States

Terminal states are `DONE | FIX | SPLIT | BLOCKED`; `RETRY` is a transition,
produced only by the controller. `next_path` mapping:

| Decision | next_path |
|---|---|
| `DONE` | `FINALIZE` |
| `FIX` | `TARGETED_FIX` |
| `SPLIT` | `DECOMPOSE_INTO_SUBTASKS` |
| `BLOCKED` | `HUMAN_OR_POLICY_INTERVENTION` |

Terminal decisions are produced exclusively in
`runtime/controller/controller.mjs` — never by a worker claim and never by a
majority vote.

## Security Hard Block

Invariant: `blocking == true` AND `severity >= HIGH` → `BLOCKED` with reason
`BLOCKING_HIGH_OR_CRITICAL_FINDING`, even when correctness and quality reviews
report PASS. There is no majority vote. Decision priority in
`runtime/controller/review-decision.mjs`:

1. Security Hard Block → `BLOCKED`,
2. any `SPLIT` recommendation → `SPLIT`,
3. any correctable non-blocking review finding → `FIX`,
4. everything green → `DONE`.

Severity is an ordinal rank (`INFO/LOW/MEDIUM/HIGH/CRITICAL`) defined in
`runtime/controller/severity.mjs`; unknown severity fails closed.

## Observability

`runtime/observability/run-events.mjs` emits `ecosystem.run-event.v1` records.
Every event keeps the same `run_id`. Minimum fields per event: `run_id`,
`phase`, `job`, `attempt`, `timestamp`, `status`, `duration_ms`. Optional
fields: `agent`, `provider`, `model`, `input_fingerprint`,
`output_fingerprint`, `failure_signature`, `strategy_delta`, `contract_in`,
`contract_out`. Fingerprints are sha256 hashes over `stableJson` (reusing
`scripts/lib/mcp-preflight.mjs`). No secrets and no full prompts are emitted as
default telemetry; `hasSecretLeak` guards the event stream.

## FIRST_BAD_BOUNDARY

`runtime/controller/first-bad-boundary.mjs` computes the first failing boundary
from the ordered phase history (`TASK, BASELINE, RESEARCH, PLAN, PLAN_GATE,
BUILD, VERIFY, REVIEWS, CONTROLLER`). The pipeline collapses per-phase status
to the final attempt state, so a bounded retry that eventually succeeds reports
no first bad boundary, while a run ending in failure reports the exact first
failing phase (e.g. `VERIFY`). The controller attaches `first_bad_boundary` and
`phase_history` to the terminal decision.

## Native OpenCode Integration

`runtime/adapters/native-opencode.mjs` is a seam, not a competing
planner/builder:

```
Native Plan → ecosystem.plan.v1 → PLAN_GATE → Native Build → ecosystem.build-result.v1
```

It exports `parsePlanText`, `fromNativePlan`, `toNativePlan`, `runNativeBuild`,
`validateNativePlanContract`, `validateNativeBuildResultContract`, and
`createBuildInput`. Native OpenCode behavior itself stays in OpenCode; the
runtime consumes only contracts.

## Backward Compatibility

The new runtime path is purely additive: existing agents, skills, policies and
plugins were not changed; existing tests were not rebuilt (they were only
registered in the canonical test manifest `test/test-manifest.json` and their
files added to the validator existence list compared by
`scripts/validate-ecosystem.mjs` against the `EXPECTED_TEST_FILES` count).
Legacy classification aliases (e.g. `GREEN_SAFE` as an input alias for
`VERIFIED_IN_SCOPE`) remain in place.

## Known Limitations

- Windows host without Developer Mode/admin cannot create symlinks →
  symlink-dependent security/integration tests fail with `EPERM` and are
  classified `NON_BLOCKING_HOST_LIMITATION` by `scripts/validate-ecosystem.mjs`
  (pre-existing, unrelated to this runtime).
- The verify layer strips `NODE_TEST_CONTEXT` from spawned children so nested
  `node --test` invocations actually execute (without this, Node skips nested
  test runs and exits 0 → false green).
- The native OpenCode seam consumes plan text/plan data via the adapter; the
  vertical-slice tests inject a deterministic build executor so the pipeline is
  fully testable without a live LLM backend.
