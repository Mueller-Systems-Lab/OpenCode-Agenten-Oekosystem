Quick start

From URL to a verified OpenCode project.

The CLI is the primary human path. It installs into the project you name and keeps existing user-owned configuration in place.

01

Install the CLI

Pin the stable release with uv.

uv tool install ocae-cli --from git+https://github.com/xxammaxx/OpenCode-Agenten-Oekosystem.git@v1.0.7
02

Install the ecosystem

Run preflight, review the plan when needed, then apply.

ocae doctor .
ocae install .
03

Verify and connect

Verify discovery, then optionally enable bare-URL handoff.

ocae verify .
ocae integrate opencode

Preview first with ocae install . --dry-run. Existing providers, models, user agents, plugins, and project configuration are preserved.

Governance / safety

Safety is part of the install surface.

OCAE makes capabilities explicit and fails closed when source, scope, integrity, or host state cannot be verified.

↯

Fail-closed decisions

Capability profiles, MCP preflight, conflict checks, and source-lock integrity gate execution.

⌁

Preserve the project

Existing config, providers, models, user agents, and third-party plugins are merged conservatively.

↩

Recoverable changes

Backups precede mutation. Provenance, audit trails, idempotence, and rollback keep state reviewable.

∅

Secrets stay out

Secret contents are not read by default, and MCPs remain disabled unless explicitly enabled.

Capabilities

Core is ready; integrations stay explicit.

Core product

Bootstrap, CLI, 13 agents, profiles, Governance Plugin, MCP preflight, source locks, backup, rollback, update, and verification.

Optional paths

Hermes adapter, Playwright visual QA, and additional MCP integrations are supported compatibility paths, not prerequisites.

Harness boundary

generic.v1 is the safe default. No model-specific profile is currently promoted.

No-provider install

Without credentials, the core can still be prepared and reports CORE_READY with PROVIDER_NOT_CONFIGURED.

Requirements / known limitations

Designed for an existing OpenCode project.

Requirements

  • Python 3.11+
  • uv and Node.js
  • OpenCode for discovery and verification

Known limitations

  • Hosts without the required symlink capability fail closed.
  • Provider credentials are host-owned and optional for core installation.
  • Model-specific harness optimization is not promoted.
