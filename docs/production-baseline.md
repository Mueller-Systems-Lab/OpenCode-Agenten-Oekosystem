## Canonical architecture

`LLMs ARE WORKERS. LLMs ARE NOT THE CONTROLLER. CONTRACT-FIRST. NOT AGENT-FIRST.`

There is exactly one runtime (`runtime/run.mjs`), one deterministic controller
(`runtime/controller/controller.mjs`), and one workflow composition
(`runtime/pipeline/pipeline.mjs`). No second runtime, no second controller, and
no workflow framework exist or are planned.

## Canonical execution path

```text
OpenCode chat.message
  → bootstrapTask
  → runtime/run.mjs: enterRun
  → ecosystem.task.v1 + run_id
  → capability/MCP baseline preflight
  → research → plan → PLAN_GATE → build → verify → reviews
  → deterministic controller
  → ecosystem.decision.v1 (DONE | FIX | SPLIT | BLOCKED)
```

The plugin entry is `.opencode/plugins/canonical-governance.mjs`. The installed
counterpart is generated by `scripts/install-governance.mjs`. A canonical
runtime entry failure is fail-fast and observable as
`CANONICAL_RUNTIME_UNAVAILABLE` / `RUNTIME_ENTRY_BLOCKED` with
`fallback_attempted=false`; it never starts a legacy execution path.

## Terminal states

The deterministic controller emits exactly four terminal states — there is no
fifth global terminal class:

```text
DONE    → FINALIZE
FIX     → TARGETED_FIX
SPLIT   → DECOMPOSE_INTO_SUBTASKS
BLOCKED → HUMAN_OR_POLICY_INTERVENTION
```

`RETRY` is a transition, not a terminal state. The controller, not a worker
claim, is the sole terminal authority.

## Critical runtime invariants

```text
CANONICAL_RUNTIME_MANDATORY
NO_SILENT_LEGACY_FALLBACK
CONTROLLER_SOLE_TERMINAL_AUTHORITY
PLAN_GATE_UNBYPASSABLE
VERIFY_MANDATORY
RETRY_AUTHORITY_CANONICAL
SECURITY_HARD_BLOCK
RUN_ID_IMMUTABLE
FIRST_BAD_BOUNDARY_STABLE
NO_SECRET_LEAK
WORKER_SUCCESS_NOT_TERMINAL_EVIDENCE
TEST_RUNNER_EXHAUSTIVE
```

Semantics:

- A single `run_id` correlates task entry, pipeline work, and events; retries
  reuse the same `run_id` with a different attempt, and no phase may replace it.
- Capability and MCP preflight is fail-closed where required.
- Build cannot execute after a rejected plan gate (`PLAN_GATE_REJECT →
  BUILD_CALLS=0`).
- Verification is mandatory between build and reviews; build success never maps
  directly to `DONE`.
- Retry is bounded: `failure_signature` exists AND `strategy_delta` is
  meaningful AND `attempt < max_attempts` AND an identical failed retry is not
  repeated. There is exactly one retry controller.
- `blocking=true AND severity>=HIGH` is a hard block → `BLOCKED`. No majority
  vote, no worker override, no legacy bypass.
- Worker self-reports are never terminal evidence.
- The first bad boundary is derived from the collapsed phase history at the end
  (a legitimate retry that eventually passes is not mis-classified by an
  intermediate failure).
- Canonical runtime failure never silently falls back to legacy execution.
- Evidence uses fingerprints and normalized failure signatures, not full prompts
  or credentials.
- Linux symlink `EPERM` is a real failure; the historical Windows symlink
  exception is strictly gated to `win32`.

## Production Sentinel

`scripts/lib/production-sentinel.mjs` is the deterministic drift-watcher for the
frozen runtime. It is invoked by `scripts/validate-ecosystem.mjs` and reports a
`PRODUCTION_SENTINEL: PASS|FAIL` line plus per-invariant `SENTINEL_<ID>` lines.
It is also exercised standalone by `test/controller/production-sentinel.test.mjs`
(positive current-baseline proof plus isolated negative drift proofs).

Checks are structural — module resolution, imports/exports, contract IDs,
runtime file lists, installer manifests, and validator outputs. Comments or
formatting changes never trigger drift.

The sentinel guards, per invariant:

| Invariant | What is checked |
|---|---|
| `CANONICAL_RUNTIME_MANDATORY` | `runtime/run.mjs` exists and exports `runTask`/`enterRun`/`enterTask`; the plugin imports it, reaches `enterRun`, keeps the `chat.message` hook, and is fail-fast |
| `NO_SILENT_LEGACY_FALLBACK` | no legacy module import, legacy marker, or legacy call inside any `catch` block of the plugin/installer/runtime entry |
| `CONTROLLER_SOLE_TERMINAL_AUTHORITY` | controller `decide` exists; terminal states/next-paths canonical; final decision created from the controller and validated |
| `PLAN_GATE_UNBYPASSABLE` | plan gate module exists; pipeline blocks build on `!planGate.approved` |
| `VERIFY_MANDATORY` | `runVerification` exists; controller gates on `verification.passed`; no DONE without reviews |
| `RETRY_AUTHORITY_CANONICAL` | single `evaluateRetry` consumer (the controller) |
| `SECURITY_HARD_BLOCK` | `blocking && severity>=HIGH → BLOCKED`; no majority vote/override |
| `RUN_ID_IMMUTABLE` | run_id created once in the task contract; `CONTRACT_INVALID` on replacement |
| `FIRST_BAD_BOUNDARY_STABLE` | first bad boundary derived from collapsed phase history |
| `NO_SECRET_LEAK` | high-confidence secret patterns absent from the runtime surface |
| `WORKER_SUCCESS_NOT_TERMINAL_EVIDENCE` | DONE only from hard-gates-green controller path |
| `TEST_RUNNER_EXHAUSTIVE` | `npm test` is canonical; all non-empty manifest groups execute; failures aggregate; `--json` exists |
| `INSTALLER_SENTINEL` | installer ships every canonical artifact and no legacy execution artifact |
| `LINUX_SYMLINK_INVARIANT` | symlink EPERM masking is win32-gated |
| `VALIDATOR_TIMEOUT_INVARIANT` | manifest-aware outer timeout; no hard 120s cutoff |
| `BASELINE_MANIFEST` | `runtime/production-baseline.json` matches canonical structure |
| `BASELINE_FINGERPRINT` | live structural fingerprint equals the recorded baseline fingerprint |
| `CONTRACT_SENTINEL` | all required contract IDs exist in `runtime/contracts/` |

Negative drift proofs (isolated fixtures — real repository files are never
deleted and rewritten):

```text
MISSING_RUNTIME_NEGATIVE=pass
MISSING_CONTRACT_NEGATIVE=pass
LEGACY_FALLBACK_REINTRODUCTION_NEGATIVE=pass
INSTALLER_DRIFT_NEGATIVE=pass
INVALID_MANIFEST_OR_EQUIVALENT_DRIFT_NEGATIVE=pass
```

## Baseline fingerprint

`runtime/production-baseline.json` records a structural fingerprint
(`c3256b558463fc7d63c36958df317a872a8836ca2739cddd659f0cefd9d17971`) computed
from stable properties only — contract IDs, terminal states + next paths,
critical invariant IDs, installer artifact dest names, and non-empty manifest
group names. Harmless text edits never drift the fingerprint; removing or
changing a contract, terminal state, invariant, artifact, or manifest group
does. The sentinel fails on mismatch.

## Test harness semantics

The canonical runner executes every file in `test/test-manifest.json`, aggregates
all groups, does not stop at the first failing group, and exits non-zero if any
real failure occurs or the expected and executed file counts differ. `--json`
provides the machine-readable aggregate. The runner is contract-tested by
`test/harness/runner-contract.test.mjs`.

## Validator semantics

`validate-ecosystem.mjs` computes a finite outer timeout from the manifest: the
sum of effective per-file timeouts (default 300,000 ms, with manifest overrides),
plus 180,000 ms suite grace and 5,000 ms per-file spawn overhead. If the
manifest cannot be read, it uses a 3,600,000 ms fallback. The outer timeout must
not truncate a legitimate manifest-authorized inner timeout. Test failures are
`RED_BLOCK`, not a warning; unavailable execution is reported separately. The
validator internally re-runs the canonical suite; this redundancy is known and
documented, and its performance is not optimized in this milestone.

## Installer baseline

The canonical installer is `scripts/install-governance.mjs`. It supports dry-run
by default, explicit `--apply`, JSON reporting, runtime detection,
backup-before-write, source-lock generation, OpenCode/Hermes adapter
installation, post-apply validation, and rollback. The distribution path is
`ocae-cli`; its documented sequence is `ocae doctor .` → `ocae install .` →
`ocae verify .`. The installer must preserve foreign/user configuration and fail
closed on name conflicts or source-lock tampering. It installs the canonical
runtime artifact set (`runtime/run.mjs`, `runtime/contracts/`,
`runtime/controller/`, `runtime/pipeline/`, `runtime/baseline/`,
`runtime/adapters/`, `runtime/reviews/`, `runtime/observability/`, and the
canonical governance plugin hook) and does **not** install legacy execution
components (`runtime/agent/run-state.mjs`, `runtime/agent/start.mjs`).

## Fresh-Install Sentinel

`scripts/fresh-install-sentinel.mjs` proves, against a real isolated temporary
target, that a fresh install yields the canonical runtime:

```text
Installer Source → Fresh Target → Canonical Runtime Installed →
Canonical Entry Resolvable → Runtime Canary Executes → No Legacy Execution
Reachability
```

Proofs included: installer `VERIFIED_IN_SCOPE`, canonical artifacts installed,
real module import probe of the installed `runtime/run.mjs`
(`runTask`/`enterRun`/`enterTask`), a harmless runtime canary
(`CONTRACT_INVALID` deterministic abort), and absence of legacy execution files,
plugin markers, and manifest entries. The proof is reproduced automatically by
`test/install/fresh-install-sentinel.test.mjs` and on demand via
`node scripts/fresh-install-sentinel.mjs`.

## Required revalidation

A `RUNTIME_CRITICAL_CHANGE` must:

1. receive a new baseline commit (the old baseline remains historical);
2. re-run `npm test` with the manifest aggregate;
3. re-run `node scripts/validate-ecosystem.mjs` (includes the Production
   Sentinel);
4. re-run relevant installer, source-lock, credential/redaction, no-fallback,
   and rollback checks;
5. refresh canonical-path, terminal-state, artifact, and observability evidence;
6. record fresh-install (`node scripts/fresh-install-sentinel.mjs`) and
   production-sentinel evidence before claiming a freeze.

For Security/Entry/Retry/Plan-Gate changes, the corresponding negative/bypass
tests must additionally be re-run.

## Rollback principle

Rollback is backup-based and reversible: create a recorded backup before
mutation, restore only from that backup, validate the restored managed state and
source-lock, then inspect the resulting evidence. If integrity, provenance, or
post-rollback validation cannot be established, fail closed rather than
continuing execution.
